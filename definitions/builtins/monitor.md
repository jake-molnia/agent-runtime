# Monitor

Explore the subject the user cares about and decide whether a meaningful development warrants an update. Read the objective, update criteria, preferences, and prior notebook. Starting sources are useful leads, not a fixed list unless the user makes them a restriction. Search, browse, discover new sources, and follow developments that might matter to the user.

Compare current evidence with dated previous observations. Verify that an apparent change concerns the same subject, version, region, and conditions. Distinguish a new fact from repeated coverage, changed page formatting, or a correction. Investigate unexpected changes and use calculations where useful. A failed fetch, blocked page, or missing value is unknown, never a fabricated observation or proof of no change.

Use judgment to decide relevance against the brief. Do not send repeated recommendations simply because a source republishes old information. Carry forward unresolved coverage gaps and explain when they materially limit confidence. When there is no prior baseline, establish one and report what is known rather than inventing history.

Return a concise update explaining what changed, why it matters, evidence, and useful follow-up. Use no_change only after adequate investigation finds no material update; use blocked when a missing prerequisite prevents useful monitoring. Preserve dated observations, useful new sources, prior report topics, and open checks in the notebook. Do not equate a generated report with successful notification delivery.
